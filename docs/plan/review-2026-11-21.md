# Code review of 2026-11-21: findings and work list

A full review of the component after the many refactors: is every mechanism that several
sources share written once, so a new streaming source only adds its own behaviour; and are there
logic bugs, duplicated code or style problems. Five read-only reviews covered the provider layer,
the per-source plumbing (inputs, HTTP, caches), the library window, the player window and
rendering, and the media / lyrics / download / CD modules. This file is the work list; items are
ticked as they land. The owner decides only what is marked **owner**.

## Phase 1: shared core module

Plumbing every source uses lives in `netease/` or is copy-pasted.

- [x] `core/`: json, log (`glasswave.log`), paths (`ProfileRoot`, `ProfileDir`), task queue moved
      out of `netease/`; no module outside `netease/` includes a `netease/` header for plumbing.
- [x] `core/text.h`: one `Utf8` / `Wide` / `LowerAscii` instead of ~35 private copies; `url.h`,
      `hex.h`.
- [x] `core/file.h`: `WriteFileAtomic` / `ReadFileLimited` instead of six hand-written atomic
      writes (one, the downloaded `.lrc` sidecar, replaced the old file even after a failed write).
- [x] `core/signal.h`: one listener registry (radio and CD called listeners removed earlier in the
      same pass).

## Phase 2: bugs

Provider layer
- [x] `Done` callbacks dropped: Apple `Post*` on a generation change, refresh and favorite-page
      waiters cleared uncalled (the language-change notification can be lost), NetEase station /
      home / suggestion reads on abort. Contract written into `provider.h`.
- [x] Apple holds `m_mutex` while the catalog writes or deletes files (`PutIfCurrent`,
      `CompleteRefresh`).
- [x] Apple `Post` uses a raw queue pointer after unlocking (late post from another thread).
- [x] NetEase rewrites all of `songs.tsv` on the main thread for every list page.
- [x] `ListPolicy` overrides duplicate the base; NetEase ignores an explicit cache override for
      search and persists recommended playlists.
- [x] Apple's capabilities omit `SimilarArtists` although it serves similar artists.
- [x] NetEase: download date in local time (display uses UTC+8); `ToArtists` O(n*m);
      `FetchSongDetails` dereferences the abort before checking it; session has no account
      generation, so a refresh racing a sign-out restores the old account.

Inputs, HTTP, caches
- [x] Apple transfer resume treats a cache write failure (disk full) as a cut; no total resume cap.
- [x] Apple's refused-item path spends the shared skip budget from a prefetch thread.
- [x] Art absence: an explicit refresh does not clear "missing" records on disk; the generation
      is global across providers.
- [x] Image cache clamps every body at 20 MiB, so the 64 MiB limit for originals is dead.
- [x] Image invalidation prefix `apple:album:12` also matches `apple:album:123`.
- [x] Audio cache: double flush, `Cancel` blocks on the commit mutex across disk IO;
      `Manager::Open` creates files under the manager lock.
- [x] Apple bridge errors drop the transport reason; Apple lyrics search throws above 32 results.
- [x] Cookie / login details: unread flag, secrets not zeroed, corrupt `session.dat` kept,
      login dialog wakes every second, window class registered on every show.

Media, downloads
- [x] aria2 `Ensure` holds the global mutex across the 16 MB install and engine start (UI freeze).
- [x] Downloads: pause then resume can run one item on two workers; an abort while tagging leaves
      an item that fails forever ("Cannot rename").
- [x] Scheduler: `timeQueued` stays set after `InvalidatePosted` (ticks stop); `Start` after
      `Shutdown` is dead; `RebuildCoreQueue`'s catch repeats the failed operation; a user Stop
      while a track is still opening reads as a failed start and plays the next one (fixed for
      every Stop of Glasswave's, `StopRequested`; foobar2000's own Stop cannot be told from a
      failed open, which the SDK does not document).
- [x] Radio: `PlayQueue` result ignored (an active station with an empty queue); listener only
      attached if the scheduler already exists.
- [x] Play stats rewritten synchronously at every track start.
- [x] LRC: `[Chorus: x2]` dropped as a tag. `[h:mm:ss]` stays: "[01:02:30]" is a valid
      centisecond time too, so no rule tells the two apart.

Player window and panes
- [x] Shuffle / repeat dim in an inactive window (caught by an enum range meant for caption
      buttons).
- [x] Player Stop does not cancel a pending play (the library window's does).
- [x] Seek head ticks every vsync while the control bar is hidden; lyrics ask for frames for the
      whole song even when only lines are timed.
- [x] First-show mini rect uses the primary monitor's DPI; `Close` leaves the bubble timer armed;
      shell glue posts to a possibly destroyed owner.
- [x] No device-loss handling (retained surfaces, `win7::Resources` bitmaps, the pane's DC).

Library window
- [x] `SongPage::Start` can install two sources when the provider answers synchronously.
- [x] Loading text restored by comparing raw `ListSource*` and the translated string.
- [x] Artist page follow state never refreshed; album page offers "Uncollect" without the
      capability guard and never "Collect"; all-favourites misses providers signed in later.
- [x] Nav pane ignores a facet-only section change.
- [x] Rating message in the list view is untranslated.

## Phase 3: provider layer generalization

- [x] `FetchListPage` is the only read entry; the ~16 per-kind virtuals and `Cached*` go (NetEase
      keeps two diverging implementations of every list today).
- [x] `Provider::NeedsAccount(query)`; "Please sign in to <name>" built once from `Name()`.
- [x] Shared generation-gated executor (Post / PostMutation / PostDetail / PostMain).
- [x] Shared account gate and bootstrap-snapshot save; one session-reset function per provider.
- [x] Shared library-edit overlays (albums, playlists, follows, songs) mirroring
      `SetFavorite` / `WriteFavorite`; the same optimistic behaviour on every source.
- [x] One `stream::Catalog` over `stream::*` records (hint queue, TSV persistence, handles,
      merge-on-restore); NetEase's lossy record round trip goes.
- [x] Split Apple's 890-line `FetchListPage`; NetEase's id-snapshot paging written once.

## Phase 4: inputs, art, HTTP

- [x] One resumable fetcher (Range, 206 / 200 / 503, stall and total caps) for both inputs; NCM
      stops resuming with `seek()` on an HTTP reply.
- [x] `EncodedInputBase`: cache-entry naming, recall / remember source, decode-seek reopen, the
      catch ladder; Atmos rendering independent of the byte source.
- [x] One album-art extractor template over a source's traits; NCM's `CoverKind` replaced by
      `stream::ArtKind`.
- [x] One JSON-over-HTTP call (timing, logging, unified transport / status errors).
- [x] Prefetch context token from the provider instead of hard-coded NetEase / Apple settings
      (`Provider::PlaybackSettings`).
- [ ] Test hooks (`ProbeTransactionTag`, `g_probe*`, `RunTestManifestCommitPause`) out of
      production paths where a seam is cheap. Checked: the list cache's hooks compile only with
      `GLASSWAVE_LISTS_TESTING` (no production cost); Apple's probe tag is a scoped bridge
      override the mock bridge needs. Open: the scheduler's `g_probeEnabled` branches (six) want a
      playback-driver seam, which is not cheap.

## Phase 6: media, lyrics, CD

- [x] Providers contribute lyrics searchers (no `applemusic` include in `lyrics/scripts.cpp`).
- [x] CD behaviour registered as a path behaviour (no `cdda://` checks in lyrics / play stats /

- [ ] Scheduler: core-queue snapshot, physical-order and checkpoint helpers; checkpoint through
